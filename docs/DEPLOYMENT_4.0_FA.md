# راهنمای استقرار مرحله اول ورق ۴.۰ — فقط معرفی و اطلاعات کتاب

**هشدار: این بسته برای انتشار تجاری/پرداخت واقعی نیست.** پیش از درمعرض‌عموم گذاشتن، شخص مسئول باید موارد حقوقی، حقوق نشر تصاویر، اطلاعات فروشگاه، تأیید داده‌ها، تجربه مرورگر واقعی و امنیت زیرساخت را بررسی کند.

## تهیه و ارتقا

۱. سورس را در مسیری مانند `/opt/varaq` خارج از document root قرار دهید و دسترسی فایل‌ها را محدود کنید. 
۲. یک حساب کاربری لینوکس بدون sudo برای سرویس بسازید؛ Node.js ۲۲.۱۳+ نیاز است. `npm install` لازم نیست.
۳. از محل نصب قبلی ۳.۹ یک نسخه `node backup.js` تهیه و `node verify-backup.js PATH` آن را کنترل کنید. نسخه پشتیبان باید خارج از سرور نیز نگهداری امن/رمزگذاری‌شده داشته باشد. مسیر `storage` قدیمی را به عنوان `DATA_DIR` اختصاص دهید و از ویرایش/جایگزینی آن در ZIP خودداری کنید.
۴. رمز اولیه حساب مدیر باید در محیط محلی به رمز قوی عوض شده باشد؛ سرور عمومی بدون حساب مدیر آماده‌شده نباید منتشر شود.
۵. از `PUBLIC_PREVIEW.env.example` برای برنامه‌ریزی متغیرهای محیطی استفاده کنید؛ مقادیر را بعد از تأیید مستقل تنظیم کنید.

```sh
export DATA_DIR=/srv/varaq-data
export HOST=127.0.0.1
export PORT=3030
export PUBLIC_URL=https://books.example.org
# چهار مقدار زیر تنها پس از تأیید واقعی و مستند:
export VARAQ_LEGAL_REVIEWED=1
export VARAQ_MEDIA_RIGHTS_REVIEWED=1
export VARAQ_BROWSER_QA_APPROVED=1
export VARAQ_PUBLIC_INDEX=1
node preflight.js --strict-preview
./PUBLIC_PREVIEW_LINUX.sh
```

۶. سرویس را فقط روی loopback نگه دارید و TLS را روی reverse proxy معتبر (Caddy، nginx و غیره) با ریدایرکت HTTP به HTTPS، محدودیت نرخ درخواست و لاگ کم‌داده فعال کنید؛ گواهی و دامنه آزمایشی باید به دامنه واقعی تغییر کنند.
۷. یک نمونه ساده تنظیمات Caddy (مقصد و دامنه را اصلاح کنید):

```caddyfile
books.example.org {
    encode zstd gzip
    reverse_proxy 127.0.0.1:3030
    header {
        X-Content-Type-Options nosniff
        -Server
    }
}
```

۸. قبل از بازکردن DNS عمومی: `/health`، `/robots.txt` و `/sitemap.xml` را بررسی کنید. `GET /health` باید `orders_mode: public_readonly` داشته باشد. `POST /demo-order` حتی با فرم معتبر باید `403` بگیرد. وضعیت سبد فقط اطلاعاتی است. پس از انتشار یک تست مرورگرهای مختلف و بازیابی بکاپ انجام دهید.
۹. تا زمانی که هر چهار فلگ تأیید فعال نباشد، noindex فعال باقی می‌ماند و sitemap عمومی 404 است؛ برای انتشار واقعی از فلگ‌ها به عنوان راه دورزدن مجوز استفاده نکنید.

## سیاست امنیتی

- هرگز پوشه `storage`, `backups`, مدارک خصوصی فروشندگان یا فایل SQLite را از طریق وب‌سرور به اشتراک نگذارید.
- بکاپ حساس است و به‌صورت پیش‌فرض رمزگذاری‌شده نیست؛ انتقال آن را با TLS و نگهداری را با رمزگذاری در سطح دیسک/بکاپ انجام دهید.
- از قراردادن نسخه عمومی و محلی روی **یک دیتابیس هم‌زمان** خودداری کنید؛ ارتقا و بکاپ در پنجره خاموشی کنترل‌شده انجام شود.
- `PUBLIC_URL` باید HTTPS و فقط یک origin ثابت بدون path باشد. در تولید اسکریپت بالا باید اجرا شود تا چک‌لیست پیش از انتشار fail-closed بماند.
- صفحات حقوقی/تماس در سورس قالب/نمونه‌اند؛ تا تکمیل مشخصات واقعی و بازبینی حقوقی آنها روی یک دامنه واقعی منتشر نکنید.
- آزمون‌های خودکار به‌معنای ممیزی نفوذ و تأیید امنیت نهایی نیستند.
