# راهنمای امن استقرار اولیه ورق ۳.۹ (مخصوص مسئول فنی)

**این راهنما برای اجرای آزمایشی و انتشار اطلاعاتی مشروط است، نه فعال‌سازی فروش واقعی.** قبل از استقرار عمومی، آزمایش نفوذ و بازبینی حقوقی/محتوایی مستقل لازم است.

## سرور

- Node.js ۲۲.۱۳ به بالا (ترجیحاً ۲۴ LTS)، دیسک پشتیبان، دسترسی محدود و HTTPS با reverse proxy معتبر (Caddy / nginx یا مشابه).
- Node را با حساب سیستمی بدون دسترسی مدیریتی و با مجوز اختصاصی برای داده‌ها اجرا کنید. فایل‌های `storage` نباید در ریشه عمومی وب‌سرور یا پوشه سرو محتوا قرار گیرند.
- سرویس Node فقط روی loopback (`HOST=127.0.0.1`, `PORT=3030`) گوش کند؛ فقط reverse proxy باید به آن متصل شود. HTTPS، گواهی معتبر، ریدایرکت HTTP به HTTPS، محدودیت درخواست و لاگ را در reverse proxy تنظیم کنید.
- `PUBLIC_URL` باید دقیقاً مبدأ عمومی HTTPS (بدون مسیر اضافی) باشد؛ نمونه `https://books.example.org`. از قراردادن رمز، API key و اطلاعات واقعی در فایل نسخه کنترل استفاده نکنید.

## نمونه دستور Linux (متغیرها باید متناسب با سرور تغییر کنند)

```sh
cd /opt/varaq
export DATA_DIR=/srv/varaq-data
export HOST=127.0.0.1
export PORT=3030
export PUBLIC_URL=https://books.example.org
node server.js
```

پس از آماده کردن دامنه و **قبل از انتشار**:

```sh
node backup.js
node preflight.js
node preflight.js --json
node preflight.js --strict-preview
npm test
```

متغیرهای `VARAQ_LEGAL_REVIEWED=1`، `VARAQ_MEDIA_RIGHTS_REVIEWED=1` و `VARAQ_BROWSER_QA_APPROVED=1` صرفاً اظهار تأیید انسانی‌اند؛ فقط پس از انجام مستند مراحل مربوطه آن‌ها را برای اجرای `preflight` تنظیم کنید. به‌هیچ‌وجه معادل صدور مجوز، تست واقعی یا اسکن امنیتی نیستند.

## عملیات و بازیابی

- پیش از هر ارتقا، سرویس را متوقف و نسخه پشتیبان سازگار تهیه/تأیید کنید. `node backup.js` یک SQLite snapshot سازگار همراه با رسانه‌های محلی (جلدها، بنرها، مدارک فروشنده) و manifest هش‌دار می‌سازد.
- لااقل یک نسخه بکاپ **بیرون از همان سرور** و محدود به افراد مجاز ذخیره کنید، چون مدارک محرمانه فروشگاه داخل بکاپ وجود دارد. این بکاپ به‌صورت پیش‌فرض **رمزگذاری‌شده نیست**. انتقال و نگهداری رمزگذاری‌شده را در لایه زیرساخت تنظیم کنید.
- `node restore-backup.js "BACKUP_DIR" "NEW_STORAGE_DIR"` هرگز مسیر موجود را بازنویسی نمی‌کند. پس از بررسی دیتابیس جدید، با خاموش‌کردن سرویس مسیر `DATA_DIR` را به پوشه بازیابی‌شده تغییر دهید.
- بکاپ فقط با آزمون بازیابی در یک مقصد جدا قابل اتکا است؛ سلامت hash به‌تنهایی کفایت نمی‌کند.
- `node preflight.js --strict-sales` در ۳.۹ باید با کد ۱ برگردد چون پرداخت واقعی غیرفعال است. **هرگز از این نسخه برای دریافت وجه مشتری استفاده نکنید.**

## محدودیت‌ها

تست‌های لوکال جای تست لود، بکاپ زمان‌بندی‌شده خارج از سرور، مانیتورینگ عملیاتی، فایروال، اسکن وابستگی‌های پلتفرم و آزمون مرورگری روی دامنه نهایی را نمی‌گیرند. محدودسازی ورود مبتنی بر IP اتصال است؛ اگر سرویس پشت proxy اجرا می‌شود، سامانه تشخیص IP و سیاست anti-abuse باید در لایه proxy و بعد از threat-model مناسب بازبینی شود.
