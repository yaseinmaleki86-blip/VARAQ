# ورق ۷.۹ — تشخیص خطای عملیاتی و آماده‌سازی استقرار

## تغییرات کاربردی

- **ابزار وضعیت عملیاتی فقط‌خواندنی**: `OPERATIONS_STATUS_WINDOWS.bat` یا `node tools/ops-status.js`، برای بررسی نسخه Node، درستی اتصال امن عمومی، bind شدن سرویس به loopback، خواندن سالم SQLite و خطاهای کلید خارجی، وجود تصویرهای اصلی و بندانگشتی و شمار رخدادهای خطا.
- **ثبت امن رخدادهای خطای ۵۰۰/۴۱۳**: اطلاعات بسیار محدود شامل زمان، کد تصادفی پیگیری، کد وضعیت، نوع کلی خطا و گروه مسیر در `DATA_DIR/operations/incidents.jsonl` ثبت می‌شود. متن خطا، پارامتر URL، رمز، کوکی، توکن، IP یا اطلاعات مشتری نوشته نمی‌شود.
- **مدیریت حجم فایل رخدادها**: هر فایل تا حدود ۲۵۶ کیلوبایت؛ بایگانی یک فایل قبلی. برای دسترسی و پشتیبانی فقط از خود سیستم یا سرور دارای مجوز استفاده شود، نه انتشار داخل `public`.
- **مراجعه به پشتیبانی**: در صورت خطای داخلی سایت، کد پیگیری نمایش داده می‌شود تا بتوان رخداد را بدون ارسال اطلاعات محرمانه پیدا کرد.
- **تغییر نسخه سرور/ابزارها به ۷.۹** و نگهداری تمام داده‌های قبلی بدون مهاجرت تخریبی دیتابیس.

## پیش‌نیاز واقعی انتشار عمومی

۱. از `BACKUP_WINDOWS.bat` نسخه پشتیبان معتبر بگیرید و در پوشه‌ای مستقل تمرین بازیابی انجام دهید. پوشه `storage` یا مسیر `DATA_DIR` را هنگام ارتقا حذف نکنید.

۲. روی سرور Linux، متغیر `DATA_DIR` به پوشه پایدار **خارج از مسیر فایل‌های عمومی** اشاره کند. `HOST=127.0.0.1`، `PUBLIC_URL=https://YOUR-DOMAIN` و TLS توسط reverse proxy مدیریت شود. دسترسی مستقیم اینترنت به پورت Node مسدود شود.

۳. `OPERATIONS_STATUS_LINUX_MAC.sh` و سپس `preflight.js --strict-preview` و `release-smoke.js --url ...` را اجرا کنید. موفقیت این‌ها تنها بررسی فنی محدود است، نه مجوز حقوقی یا انتشار تجاری.

۴. مرورگرهای واقعی گوشی و دسکتاپ، صفحه سفارش فروشندگان، لینک‌های خصوصی PDF و تعلیق مجوزها در محیط استقرار واقعی آزمایش شوند.

۵. متون پیش‌نویس، حقوق تصاویر و مالکیت توزیع PDF به تأیید انسانی برسند. پرداخت آنلاین، دانلود پولی و ارسال واقعی همچنان **غیرفعال** هستند؛ درگاه رسمی هر فروشنده هنوز متصل نشده است.

## ابزارهای آزمون

```bash
node --test tests/phase79.test.js
node tools/ops-status.js --json
node tools/operations-check.js --json
node verify-release.js
```

`ops-status.js` بدون `--strict` وضعیت را نمایش می‌دهد و داده‌ها را تغییر نمی‌دهد. با `--strict` وجود خطای فنی باعث کد خروج ناموفق می‌شود. بررسی نسخه ۷.۹ جای بررسی نهایی حقوقی، HTTPS و مجوزها را نمی‌گیرد.
